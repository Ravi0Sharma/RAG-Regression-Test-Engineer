# Karpathy guidelines

- State material assumptions and tradeoffs. Ask when unresolved choices block correct work; continue independent work.
- Define observable success before implementation. Recommend simpler options without overriding user decisions.
- Keep changes tied to the request. Match existing style; avoid speculative features and unrelated refactors.
- Remove dead code introduced by your changes. Broader cleanup only when requested.
- Verify behavior with proportionate checks. Report what passed, what failed and what remains uncertain.
